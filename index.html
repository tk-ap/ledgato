// the mental model
Think bouncer + referee + black box recorder, not just a dashboard.

A monitoring tool can tell you something bad happened. Ledgato is designed to sit at consequential boundaries so it can decide whether the action should happen at all, pause it for approval, and preserve evidence afterward.

Bouncer

Can this action cross?

Checks the requested action against the authority actually granted for this agent, task, environment, and moment.

Referee

Allow, deny, or escalate.

Low-risk authorized work can continue. Out-of-bounds work stops. Consequential ambiguity can pause for a human.

Black box

What actually happened?

Records the request, decision, approval context, downstream result, and verification evidence.

// first concrete wedge

Release assurance is the first proving ground, not the whole product.

GitHub and CI are a legible, consequential boundary: an agent-produced change is about to merge or deploy. That makes release assurance the right first customer wedge for proving the broader Agent Assurance model.

  • Before merge or deployCompare the action and reachable permissions with the approved boundary.
  • Drift becomes a real decisionResolve the crossing as ALLOW, DENY, or APPROVE instead of merely flagging it.
  • Approval stays scopedA human approval should apply to the exact consequential action, not become permanent broad authority.
  • Afterward, verify realityRead the provider state back and confirm the intended action — and only that action — occurred.

// current proof status

Separate what is implemented from what is proven.

The engine already has real enforcement-path behavior. The current stress test is specifically about whether an autonomous agent can bypass that boundary when given realistic alternate routes.

implemented

Current engine behavior

  • Enforcement gateway with ALLOW / DENY / APPROVE control flow.
  • DENY does not call the downstream adapter through the governed path.
  • APPROVE can pause and resume execution.
  • GitHub adapter can execute and verify provider state.
  • Authority, approval, discovery, and evidence surfaces exist in the current engine.
being stress-tested

What still needs stronger proof

  • That the agent cannot simply bypass Ledgato with an equivalent GitHub credential.
  • That authenticated identities cannot be spoofed to self-approve or escalate authority.
  • That alternate routes, cached credentials, replay, restart, and failure cases stay fail-closed.
  • That “DENY” corresponds to the protected downstream action remaining impossible, not merely a policy response.
// faq

Questions, answered

Is Ledgato only a release gate?+

No. Release assurance is the first concrete commercial wedge because merge and deploy boundaries are easy to understand, consequential, and testable. The broader product thesis is Agent Assurance: checking and enforcing consequential authority boundaries wherever Ledgato is integrated into the action path.

Is runtime action-level enforcement real today?+

The current engine already implements a real enforcement gateway with ALLOW, DENY, and APPROVE behavior, plus downstream execution and verification through adapters. What is not yet fully proven is bypass resistance across realistic alternate routes. The active enforcement stress test is designed to establish that evidence rather than treating a gateway DENY as sufficient proof.

What does “where integrated” mean?+

Ledgato can only stop an action if the protected capability is actually behind an enforceable boundary that the agent cannot bypass with equivalent credentials or another uncontrolled route. Integration architecture matters as much as the policy decision.

What happens when an action needs a person?+

The action should pause, present the exact requested scope, and resume only after a valid approval for that same scope. Approval should not silently widen the agent's ongoing authority.

How is this different from observability or audit software?+

Observability primarily tells you what happened. Ledgato's defining ambition is active intervention at a consequential boundary: decide whether the action may occur, stop or pause it when necessary, then verify and record the result.

Does Ledgato claim it can stop every agent exploit?+

No. The defensible promise is narrower: reduce reachable authority, gate consequential crossings where integration allows, limit blast radius, verify outcomes, and preserve evidence. The stress-test program exists to make clear which boundaries are actually verified and which remain partial or unverified.
